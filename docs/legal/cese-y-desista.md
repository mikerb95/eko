## Antes de enviar: verificación en cinco puntos

1. **Confirmar la titularidad.** El aviso del sitio y el archivo `LICENSE`
   deben nombrarte a ti. Si en algún momento se firma cesión a EKOSOLV S.A.S.,
   esta plantilla deja de servirte y pasa a ser la empresa quien requiere.
2. **Confirmar que lo copiado es tuyo.** Aislar qué elementos concretos son de
   autoría propia y descartar los que provienen de terceros (fuentes,
   dependencias, iconografía con licencia abierta, marca de EKOSOLV).
3. **Fijar la anterioridad.** Identificar el commit y la fecha en que aparece
   por primera vez el elemento copiado, y la fecha en que apareció en el sitio
   del infractor.
4. **Medir la sustancialidad.** Un color parecido no es plagio. Sirve como
   prueba: código idéntico, cadenas de texto propias reproducidas literalmente,
   nombres de clase CSS inventados por ti, comentarios del código, errores
   tipográficos replicados, estructura de datos calcada.
5. **Decidir el objetivo real.** Retiro del contenido, licenciamiento pagado,
   crédito, o indemnización. La carta cambia según cuál sea.

## Recolección de pruebas: hacerlo antes de enviar la carta

El orden importa. En cuanto reciban la carta, el sitio infractor puede cambiar
de la noche a la mañana, y con él se va la prueba.

**1. Congelar la evidencia del sitio infractor.**

```bash
# Copia completa del sitio infractor, con marca de tiempo en el nombre
wget --mirror --page-requisites --adjust-extension --convert-links \
     --no-parent -P "prueba-$(date +%F)" https://SITIO-INFRACTOR/

# Hash de cada archivo capturado: prueba de integridad de la copia
find "prueba-$(date +%F)" -type f -exec sha256sum {} \; > "prueba-$(date +%F)/HASHES.txt"
```

**2. Forzar el archivado público en el Internet Archive.** Una captura de un
tercero neutral pesa más que una tuya. Guardar tanto tu sitio como el suyo en
https://web.archive.org/save/ y anotar las URL resultantes.

**3. Anclar la fecha de tu propia obra.** El historial de git prueba
anterioridad, pero las fechas de git son alterables. Para fecha cierta:

```bash
# Hash del árbol completo del repositorio en este momento
git rev-parse HEAD
git archive HEAD | sha256sum
```

Ese hash se consigna en la carta y, si el asunto escala, se protocoliza ante
notario mediante declaración extrajuicio, o se registra la obra ante la DNDA.

**4. Registrar la obra ante la DNDA.** El registro es gratuito y se tramita en
línea en https://enlinea.derechodeautor.gov.co. No crea el derecho, pero
convierte tu titularidad en un hecho documentado con presunción de veracidad,
y evita que la discusión se vuelva tu palabra contra la suya. Se registra como
**obra de software** y, por separado, como **obra literaria** los textos del
sitio. Hacerlo ahora, no cuando aparezca el plagio.

**5. Documentar la comparación.** Una tabla de dos columnas, elemento por
elemento, con capturas alineadas y las URL visibles. Es el anexo que más
trabaja: quien la lee entiende la infracción sin conocer de código.

## Nota sobre a quién se dirige

Si el sitio infractor lo construyó una agencia o un desarrollador contratado,
conviene requerir **a ambos**: al cliente que lo publica y explota, y al
desarrollador que materializó la copia. El cliente suele resolver rápido para
no quedar en medio, y el desarrollador es quien realmente tiene los archivos.
